# V1.1 第二阶段上线配置

## 执行顺序

1. 先在 Supabase 执行 `0007_summary_import_window.sql` 和 `0008_accounts_feedback_and_permissions.sql`。
2. 在 Supabase Authentication 中关闭公开注册，由管理员创建内测账号。
3. 每个用户使用不同的随机初始密码，建议至少 12 位；不要在仓库或文档中保存密码。
4. 把管理员账号设为管理员。将下面的邮箱替换为实际管理员邮箱后，在 Supabase SQL Editor 执行：

```sql
update public.profiles
set role = 'admin'
where email = lower('admin@example.com');
```

5. 确认 `feedback-images` Storage bucket 为 Private，单文件限制为 2 MB。
6. 部署应用后分别使用普通用户和管理员账号完成验收。

## 账号处理

- 不配置自定义 SMTP，不开放注册、邀请链接或自行找回密码。
- 首次登录提示修改密码，但允许选择「暂不修改」。
- 忘记密码时，管理员在 Supabase Authentication 中重置为新的随机临时密码，并私下发给用户。
- 如需停用账号，把对应 `profiles.access_enabled` 改为 `false`。

## 验收重点

- 普通用户只能读取自己的画像与训练数据，不能打开反馈管理接口。
- 管理员首页显示反馈管理入口和未读数量；可标记已读、查看私有图片并删除反馈及图片。
- 单次反馈最多 500 字、5 张图；原图单张不超过 10 MB，浏览器压缩后单张不超过约 2 MB；每人每日最多 10 次。
- 首页可进入使用指南和反馈页面；登录页明确提示内测账号需联系管理员。
